| aspect | old (`osm_overpass.fetch_osm`) | current (`osm.py` + `base.py`) |

| host | api.openstreetmap.org | overpass-api.de |

## Recorded evidence

The fixtures under `tests/fixtures/recorded/*/osm/` were recorded by the old adapter: each says `'source': 'osm_api'` with a radius of 262.4 m. They never came from Overpass. So "OSM was fast earlier" refers to **api.openstreetmap.org**, a different service on a different host.

## What the history alone suggests

The old code never used Overpass. It called the OSM main API (`/api/0.6/map?bbox=`) with a custom User-Agent (`tcp-poc/0.2`), a 5 s connect and a 30 s read timeout, through `requests`, with the OS trust store. The S6 adapter calls a different service: the public Overpass server at `overpass-api.de`, running a regex-filtered query with `out tags geom`. A public Overpass server is shared and is often slow or busy, whereas the main API serves a plain bounding box. The difference of service is the first suspect; the User-Agent, the method and the interpreter are not different in kind (both use `requests`, both set a User-Agent, both GET). The diagnosis script tests the suspects one by one.
