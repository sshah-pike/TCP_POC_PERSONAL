## 4. Data shapes (proposed)

Catalog file v0.2 (a migration script from v0.1, run once, reviewed as a diff):

```
{schema_version: "1", catalog_version: "0.2", status, catalog_hash,        # hash over canonical JSON of entries, incl. asset sha256
 entries: [ {device_id, code, printed_as: [..], code_status: MUTCD|CLIENT_CODE|STATE_CODE|DEVICE,
             name, category, pack_device_id: "DV-W20-1" | null,
             size_source: PACK | TEXT_ONLY | SOURCE_REVIEW_REQUIRED | NOT_IN_MVP_PACK,      # sign sizes themselves live in the pack (Q1 option C)
             size_text: "see source" (non-sign devices only, informational),
             asset: {uri, sha256, size, media_type, status: PLACEHOLDER_ASSET | CLIENT_ASSET},
             notes, observed_in_drafts} ] }
```
`uri` is a store key or repo-relative asset key, never a raw path (Q6). `used_by_tas` is removed or marked informational (Q5).

Pack records (no model change): `table_def T-6H1` (key `device_code`; values `conventional_w_in`, `conventional_h_in`, `freeway_w_in`, `freeway_h_in`, `minimum_w_in`, `minimum_h_in`, unit `in`) and one `table_row` per sign with `source_ref_ids` to a quoted page. Rows with no usable value are `SOURCE_REVIEW_REQUIRED` with an SME question, as S4 does. Tables 6G-1 and 6I-1 get their own `table_def` if Q2 includes those signs.

Lookup result (what S8 and S12 receive):
```
SizeResult {device_id, road_type, column: CONVENTIONAL|FREEWAY|MINIMUM, width_in, height_in,
            status: SOURCED|SOURCE_REVIEW_REQUIRED, rule_id: "T-6H1-W20-1", pack_version, pack_hash, source_ref_ids[]}
PlaceholderStatus {uses_placeholder: bool, device_ids[], reason_code: "PLACEHOLDER_ASSET", label: "PLACEHOLDER SYMBOLS - NOT CLIENT LIBRARY"}
```
The label text is config, not code. The validator emits the standard validator-result record used in the PlanObject trace.
